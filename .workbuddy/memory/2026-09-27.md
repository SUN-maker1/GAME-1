## 15:30 【重要修正】上一轮的定位都错了，真正的根因与修复
### A. 反复切场景：真凶是 PersistentPlayer 的「自我销毁」单例，不是防误触时机
- 旧 `PersistentPlayer.Awake()` 里有 `if (Instance != null && Instance != this) Destroy(gameObject)`，配合 `OnDestroy(){ Instance = null }` 会制造**时序空窗**：
  新场景 Player 先 Awake → 把自己销毁 → 旧场景 Player OnDestroy 把 Instance 清空 → 落位时 Instance==null → PlacePlayer 直接 return → 玩家没被搬走，卡在传送点上。
- 新设计（已重写）：
  - `PersistentPlayer` **不再自我销毁**；Awake 只 `Instance = this`；OnDestroy **故意不清 Instance**（避免把有效引用清成 null）。
  - **玩家不再 DontDestroyOnLoad**。Single 加载已会销毁旧场景物体，残留重复实例才是万恶之源。跨场景状态交给存档系统，不要靠"玩家活着"来带。
  - `SceneLoader` 落位改挂 `SceneManager.sceneLoaded` 事件（时机确定，不再靠协程顺序）；新增 `FindPlayerInActiveScene()` 用 `gameObject.scene == SceneManager.GetActiveScene()` **过滤残留玩家**。
  - `ScenePortal` 加第②层保险 `SetCooldown()`（落位后 1.2s 冷却）+ `cooldownAfterArrive`；`Fire()` 里立即 `triggered/playerInside/armed` 三置位防同帧重复；`Start()` 里若 `SceneTransition.IsBusy` 直接进冷却。
  - 四层保险汇总：armed / cooldown / triggered / IsBusy，任一失效都不死循环。
- 教训：**Unity 单例千万不要在 Awake 里 `Destroy` 别人（包括自己），也别在 OnDestroy 里无条件清静态引用**——场景加载时 Awake/OnDestroy 的调用顺序不可靠。要过滤实例就用 `gameObject.scene` 比对。

### B. 走动发糊：跟帧率毫无关系；改 Point 过滤也解决不了
- 帧率只影响流畅度，不影响清晰度。**清晰度 = 贴图每像素对应多少屏幕像素。**
- 核心公式（正交相机）：
  - `每世界单位屏幕像素 k = 参考屏幕高 ÷ (2 × 正交半高)`；当前场景 k = 1080/(2×6) = **90**
  - **贴图缩放倍率 = PPU ÷ k**。只要不是整数，就有像素被拉成 2 格、有的 1 格，配合相机 SmoothDamp 跟随 → 移动时才发糊、静止时还行。
- 实测数据（工程现状）：`player1.png` **2048×2048 / PPU=100** → 倍率 1.11（非整数）→ 糊；`Placeholder_Farm.png` 512px / PPU=8 → 倍率 0.089，**缩小 11 倍**，糊得最狠；`Farm_spring_2026-09-27.png` 1280×1071 / PPU=100 / filterMode=1(Bilinear) → 倍率 1.11。
- 修复（已做）：
  - `CameraFollow` 新增 `pixelPerfect` 开关 + `AlignToPixel()`（相机位置吸附到像素网格，跟边界钳制在 Follow/SnapToTarget 两处都接了）+ `GetWorldPerPixel()` / `GetPixelsPerUnit()`。这是"移动才糊"的直接解。
  - `FarmFrameworkSetup` 新增菜单「3. 像素校准：算出当前正确的 PPU」和「4. 一键把 Assets/IMAGE 的 PPU 设为 1:1」（PPU 设为 k 的取整值；仅跳过 Placeholder_Farm/Town 两张脚本生成的图，用户自己的图会一起校准）。
- 注意：改 PPU 会改物体世界尺寸（世界尺寸 = 贴图像素 ÷ PPU）。地图变大就调小相机的 Orthographic Size，反之调大。
- 待办/提醒：占位图 512px 铺 64 单位必然糊，只是临时用；换真图后必须跑一次校准菜单。

### 修复（本轮改动）
- **`ScenePortal` 重写为星露谷式**：去掉布尔 `armed`，改为「`playerInside` + `cooldownTimer` + `triggered`」。传送成功立刻进冷却（`rearmDelay` 默认 1.2s）；落位后 `MarkUsed(playerPos)` 再进一次冷却。**关键机制**：落位时玩家与传送点重叠，Unity 不会补发 Enter 事件 → `playerInside` 保持 false → 不会二次触发；玩家走出再走进才会重新武装。

  - **「5. 一键对齐地图布局（按实际贴图尺寸重排）」**——读 `Map_Background` 的 `sprite.bounds` 实际世界尺寸，重排墙/传送点/入口点/`CameraFollow.manualBounds`/`PlayerMovement.boundary`，并**把玩家碰撞体压到 ≤1.6 单位**，最后 `ReportLayoutIssues()` 体检（贴图超地图一半、碰撞体过大、缺 SpriteRenderer 都会报警）。**换图后点一次即可全对齐。**

## 23:15 精灵尺寸自动适配工具 + 攻击独立镜像
### ① 为什么同 PPU 下攻击会变小（已量化）
实测 try2 五张图的「角色实际不透明像素高度」：
| 贴图 | 内容高 px | PPU | 世界身高 |
|---|---|---|---|
| walk_front | 511 | 400 | 1.278 |
| walk_back | 496 | 400 | 1.240 |
| walk_left / right | 493 | 400 | 1.232 |
| **attack** | **267** | 400→200(用户手调) | 0.668→1.335 |
→ attack 图里角色像素高度只有走路图的 **一半**，PPU 相同必然小一圈。用户手调 200 得到 1.335（比走路 1.24 略大 8%），工具算 **267÷1.28 ≈ 209** 才严丝合缝。
- **判据总结：PPU 相同 ≠ 尺寸相同，取决于「内容像素高度」。换任何新素材都应重跑适配。**

### ② 新增 `Assets/Editor/SpriteFitTool.cs`（菜单 `Tools ▸ 农场RPG ▸ 玩家 ▸ 精灵尺寸与脚底自动适配…`）
- 从 AnimatorController 的所有 clip 收集 PPtr 精灵曲线 → 按所属贴图分组（只处理玩家图，不碰地图）。
- 逐切片扫描 alpha>16 的包围盒 → 取该贴图**最大**内容高度 → `PPU = 内容高 ÷ 目标身高` 反算并写回 meta 的 spritePixelsToUnits。
- **同时对齐脚底**：每切片 pivot 设为 `x=内容中心/框宽, y=内容最低点/框高`，alignment=Custom(9)。这比统一 pivot 更好——顺带消除「帧内容在切片框内逐帧水平偏移」导致的走路左右晃（之前 left 图 +28→-25px）。
- 读像素需临时把 `TextureImporter.isReadable` 打开，用 **try/finally** 保证复原；`SaveAndReimport()` 后**必须重新 GetAtPath 取导入器**（旧对象可能失效）。
- 目标身高默认 1.28（=走路图现状），另有「用走路图当前身高」按钮自动测量。
- 踩坑：PNG 头读宽高只要前 24 字节（8 签名 + 8 len/type + 8 宽高），不用解压；导入 MaxSize 会缩放，要 `scale = tex.width / pngW` 校正切片 rect。
