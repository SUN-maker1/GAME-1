### ② 修 MissingComponentException（Unity 假 null 坑）
- 报错：`MissingComponentException: There is no 'BoxCollider2D' attached to "Wall_Box"`，每次编辑器 Update 抛一次。
- 根因：写了 `GetComponent<BoxCollider2D>() ?? gameObject.AddComponent<...>()`。Unity 的 GetComponent 找不到组件时返回**假 null**（C# 引用非 null，仅 `== null` 重载为 true），`??` 走 C# 引用判断所以永远不触发右边的 AddComponent，随后访问 collider.size 抛异常。
- 修复：拆成两次显式 `if (x == null) x = AddComponent...`（Unity 重载 == 判断）。`?.` 同理对 MonoBehaviour/组件不安全，string/delegate 上无碍。
- 教训入 MEMORY：本项目脚本风格检查项——禁止对 Unity Object 用 `??` / `?.` 做存在性判断。

### ④ 「实际碰撞体积比选中区域大很多」成因与修复
- 核对：ObstacleShape2D 的 Gizmo / 手柄框 / 实际 BoxCollider2D·PolygonCollider2D 三处都用同一个 `size`，数学一致，碰撞体不会自变大。
- 玩家碰撞体实测只有一个 BoxCollider2D `0.7×1`（半宽 0.35、半高 0.5），场景 Player 实例 scale 1×1×1，玩家本身很小，单靠它只留 ~0.35 单位留白，不至于「大很多」。
- 真因（高概率）：Scene 视图若转成斜 3/4 视角，`ObstacleShapeBrush.MouseWorld` 用固定 `z=0` 平面接鼠标射线，会把拖出的范围**放大且偏移**——画完看着大、且在斜视角下手柄框也偏移，于是觉得「框在这、人却被挡更远」。
- 修复 A：`ObstacleShapeBrush` 点「开始绘制」时 `Force2DView()` 自动把 Scene 切回 2D 正视角（反射取 `in2DMode`/`is2DMode`，try/catch 兜底）。
- 修复 B：`ObstacleShape2DEditor` 选中时额外画「人物会被挡边界」= 障碍物框 + 玩家碰撞半宽（黄虚框 + label），直观说明留白来源，消除「大很多」错觉。
- 提醒用户：之前斜视角画歪的区域，切 2D 后**重新画一次**才准；已有歪掉的区域可直接选中拖手柄改 size。

### ⑤ 「选择多少就是多少」——【已纠正】碰撞体必须=选中区域原样
- ⚠️ 本条第 1 版写反了：曾以为要"向内收缩玩家体型"（`playerPadding`，尺寸 `size - 2*playerPadding`）。这是错的——收缩后玩家身体反而能**探进**选中框 `p` 的距离，人能走进选区。
- 正确物理：两个碰撞体不能重叠。障碍碰撞体=选中框 `S` 时，玩家身体边缘恰好停在框上，**框内完全空着** = "选多大，人走不到多大"。玩家的碰撞体积由物理自动顶在框边，是自然缓冲，无需、也不能去减它。
- 最终改动：`ObstacleShape2D` 删除 `playerPadding` 字段；`Rebuild` 里 `boxCollider.size = size`、`Polygon` 椭圆半径 = `size*0.5`（原样）。`ObstacleShape2DEditor` 删掉 `DrawBlockBoundary` 内圈辅助线（误导性）与其调用；`FromSelection` 去掉 padding 赋值。`ObstacleShapeBrush.CreateArea` 去掉 `ob.playerPadding = ReadPlayerHalf()` 并删除 `ReadPlayerHalf()` 方法。
- 教训：**"完全贴合"= 障碍碰撞体等于选区，绝不向内收缩**。地图边界墙同理（碰撞体=地图四边）。记为 MEMORY 红线。

## F7 拖动不保存 —— 根因与修复（15:30 左右）
- **根因两处**：
  1. 台词默认写在**场景里的 NPC 组件**上（NPCInteractable.firstDialogue/repeatDialogue 内联 List<DialogueLine>）。Unity 退出 Play 模式会**回滚所有场景物体改动**，所以拖出的立绘 offsetX/Y 必然丢失。只有写在 Scene 里的 dialogueAsset（ScriptableObject）才可能留。
  2. 布局资源本身也没存住：`AssetDatabase.SaveAssets()` **只写被标记脏的资源**；Play 里改的数值不会自动 SetDirty，原来只调 SaveAssets() 等于没存。
- **修复方案（双管齐下）**：
  a) 每句立绘的位置不再写回台词，改为存在 **DialogueLayout 资源**的表里：`List<DialogueSlotOverride>`（key / offsetX / offsetY / width / height），DialogueLayout 新增 FindSlotOverride / GetOrCreateSlotOverride / RemoveSlotOverride。
     key = `OwnerId#lineIndex#slotIndex`，OwnerId = DialogueAsset 名（有资源时）否则 fallbackSpeaker（NPC 的 npcName）。DialogueManager.ShowLine 里 ApplySlotOverrides() 显示每句时套回，退出 Play 重进依然在。
     键的脆弱点：插入/删除台词会导致行号错位、同名 NPC 共享键 —— 已知，需要时再升级。

## 主菜单黑屏（22:37，两处真根因）
- 现象：Play 后连开始界面都没有，Game 视图全黑。截图 Hierarchy 里 MainMenu 物体上只剩 `Scene Loader (Script)`、**没有 Canvas** → 说明 MainMenuUI 的 Canvas 在运行时被销毁了。
- **根因 1（自毁误杀）**：`MainMenuUI.Awake` 里 `homeSceneName = gameObject.scene.name`。同物体上的 `SceneLoader.Awake` 会 `DontDestroyOnLoad(gameObject)`，把整个物体搬进 "DontDestroyOnLoad" 场景 → 这个名字取出来就是 `"DontDestroyOnLoad"`，于是之后任何一次场景加载都让 UI 认定"已离开菜单场景"→ `Destroy(canvas.gameObject)` + `Destroy(this)` → 黑屏。
- **根因 2（连锅端）**：`SceneLoader.Awake` 重复实例分支写的是 `Destroy(gameObject)`。从游戏「返回主菜单」时，新场景的 SceneLoader 发现自己不是 Instance，把整个 MainMenu 物体（含 MainMenuUI）一起删掉 → 黑屏。
- 修复：
  1. `MainMenuUI`：出生场景名改取 `SceneManager.GetActiveScene().name`（另行加了 Inspector 字段 `menuSceneName` 可手填；取到 `"DontDestroyOnLoad"` 或空值时停用自毁保护，宁可不动也不误杀）；Awake 末尾打一条诊断日志（属于场景 / 当前活动场景 / 同物体有无 SceneLoader）；同物体检测到 SceneLoader 时打警告。
  2. `MainMenuUI.MakeCanvas`：Canvas 改成**独立根物体**（去掉 `SetParent(transform)`），随 MainMenu 场景卸载；自毁时若 canvas 引用已失效则按名字 `MainMenuCanvas` 兜底清理。

  4. `DialogueManager`：同类单例自毁也改成 `Destroy(this)`。
  5. 直接改 `Assets/Scenes/MainMenu.unity`：把 SceneLoader 组件从 MainMenu 物体搬到新建的 `SceneLoader` 物体（GameObject 64818703 / Transform 64818704，SceneRoots 同步补一项），省掉用户手动重建场景。
